# 梯级水库调度演练（Cascade Reservoir Dispatch Trainer）

面向新任调度员的浏览器端经营策略游戏：玩家管理一条河上的 **4 座梯级电站**，在
**发电收益、防洪安全、下游供水** 三者之间权衡。纯 TypeScript + Canvas，零运行时依赖，
全部逻辑在浏览器本地运行。

## 启动

```bash
npm install
npm run dev        # 开发服务器 http://localhost:5173
npm run build      # 类型检查 + 生产构建到 dist/
npm run preview    # 预览生产构建
npm test           # 引擎自测（守恒 / 确定性 / 时滞 / 事件 / 批量 / 存档迁移）
```

浏览器端另有 `smoke.html`（dev 下访问 `/smoke.html`）做全页面自动化冒烟。

## 功能清单

| 模块 | 说明 |
| --- | --- |
| 主菜单 | 六个入口与操作手册 |
| 关卡选择 | 3 个预置关卡 + 自定义关卡，本地最佳星级记录 |
| 调度主界面 | Canvas 河道视图（四库水位/汛限线/机组/泄流动画）、闸门开度与机组台数控制、来水预报、事件横幅、多序列过程线图、结算、快速存档 |
| 关卡编辑器 | 改河道（拓扑/时滞/损失）、电站（水位库容曲线、闸门泄流曲线、机组）、来水参数、供水分段、突发事件、评分阈值；实时预览、一键试玩、JSON 导入导出 |
| 平衡模拟 | 4 种自动策略 × 最多 600 个派生种子批量跑，输出胜率、三星率、失败率、得分分布直方图与守恒误差 |
| 存档管理 | 带版本号的本地存档、续档、导入导出、录像导入回放 |

## 核心工程保证

- **确定性**：所有随机性来自 FNV-1a + mulberry32 的种子 PRNG（`src/core/rng.ts`），
  引擎内禁止 `Math.random`/`Date.now`。同一种子 + 同一串操作 ⇒ 逐位一致（自测含指纹比对）。
- **水量守恒**：系统边界闭合
  `期初蓄水 + 累计天然来水 = 当前蓄水 + 河道槽蓄 + 累计出口 + 累计河道损失`，
  自测相对误差在浮点舍入量级（~1e-16）。漫坝溢流同样计入出库并演进，不凭空消失。
- **河道时滞**：上一级出库按 `lagSteps` 与槽蓄权重（默认全部落在 lag 步）到达下一级，
  脉冲测试验证到达时刻精确。
- **录像回放**：一局只存操作序列与关卡快照，回放时用同一引擎重放，结果与原局一致。
- **存档版本化**：`schemaVersion`（存档结构）与 `configVersion`（配置表）分离，
  `migrateLevel` 负责把老版本补齐到当前结构，老存档始终可读。

## 目录结构

```
src/
  core/          # 纯逻辑、无 DOM：类型、PRNG、插值、来水/事件生成、引擎、策略、批量、确定性校验
  data/          # 数值配置表（4 库参数、3 关卡、评分权重）
  persistence/   # 存档/录像结构、版本迁移、localStorage、导入导出
  state/         # 屏幕路由/全局 store、对局会话、编辑器工厂
  ui/canvas/     # Canvas 河道主视图与过程线图
  ui/            # 六个页面（DOM + Canvas 混合）
scripts/         # 引擎自测脚本
```

## 玩法提示

- 每步 = 6 小时。发电流量优先占用出库能力，闸门承担剩余泄量；水位贴死水位时出库自动受限。
- 水位超汛限按超高一米每步扣分；超坝顶判漫坝（一次性重扣，局内判负但记录跑完整局）。
- 暴雨预报偏差会让预报偏大/偏小，实际来水以过程线为准；机组检修会减少可用机组台数；
  下游抽水需求变化直接影响供水保证率。
- 枯水期供水主要靠发电下泄流量，盲目关闸或停机都会拉低保证率。
